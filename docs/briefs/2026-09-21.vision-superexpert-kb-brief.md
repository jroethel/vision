# Brief: the Vision superexpert - a docs/ knowledge base that retrieves and grows

Date: 2026-09-21
Status: supersedes `2026-09-20.vision-kb-ingest-access-brief.md` (that brief covered the retrieve half only; this one is the whole system)
Stage: brainstorm output, next stage is /loop-plan

## Outcome

Turn `docs/` into a knowledge base that a developer summons with one `just -g` command to get a Vision superexpert.
The expert is a co-primary Vision schema architect and data engineer, with sysadmin as a secondary role designed-for but not built here.
The knowledge base does two jobs at once, both co-primary this time.
It retrieves the right doc at task time, and it accumulates verified learnings over sessions so the expert gets better the more it is used.
The named mechanisms in the request (knowledge base, database, knowledge graph, index, embeddings, `just -g`) were hypotheses about how, not the outcome.

Presupposition verdict, tested this session (2026-09-21): the request assumed a retrieval or memory mechanism must be built, and that assumption is mostly wrong.
Retrieval is already solved by an installed, tested tool (qmd, local hybrid BM25 + vector + rerank, no API).
The summon surface already exists as the global launcher `just -g` resolves to (`~/.config/just/justfile`, a launcher for agent CLI role sessions).
The relationship graph is already written into the docs as hyperlinks and named anchors that survive conversion.
So the work is not "build mechanisms" but "convert the docs into a clean corpus the installed tools already work over, wrap it as a summonable expert, and add a trustworthy grow loop on top."

## End artifact

This is enabling work, so it must name the first real deliverable it unblocks.
First deliverable: a developer runs `just -g vision`, and the summoned expert correctly performs one real co-primary task grounded in the knowledge base.
For example authoring or correcting a data feed's field mapping, or designing an entity subclass with the right superclass and property kinds, with the answer checkable against the live source code or the ivr testkit rather than against the dated docs.
Second deliverable, proving the grow half: a learning verified against code or ivr in one session is captured, promoted by a human, and then surfaces in retrieval in a later session.
If the knowledge base cannot yet support the first task end to end, and cannot yet carry one learning across sessions, this is not done.

## Done looks like

A developer runs `just -g vision` from anywhere and lands in a Claude Code session where the Vision expert skill is active and the qmd index is queryable, in one command.
The expert answers, over the derived corpus and never the raw HTML, which feed sets a given field and what its type is, for any co-primary feed.
The expert walks a schema relationship (a feed to a related feed, or a class to a message it inherits) by following the corpus's own preserved links, without loading unrelated files.
No single unit the expert must load to answer one question is large enough to threaten a working session, and a heavy multi-file sweep runs in a subagent so its verbose reads never fill the main window.
Every derived unit and every promoted learning points back to the frozen source or the code check it came from, so any claim is traceable.
A session's verified findings can be captured to a review queue, promoted by a human into the expert's knowledge, re-indexed, and retrieved in a later session, with nothing entering the expert's knowledge unreviewed.
A retrieved schema or feed claim is treated as unverified-as-of-retrieval, so provenance-to-origin is never mistaken for currency, and any such claim destined for a feed or schema commit is checked against the live source or the ivr testkit at use time before the commit.

## Approach

Chosen: convert the frozen docs to a clean markdown corpus with pandoc, shred only the oversized message files at their existing named anchors, stamp each unit with a provenance pointer to its frozen source, and access it through the installed qmd hybrid search plus link-following over the preserved cross-references.
Wrap that corpus as one Claude Code skill (`vision-expert`), committed in the repo, whose body is the corpus map plus the retrieval protocol and the code-is-ground-truth rule, kept small by progressive disclosure so the 6MB never lands on the context budget.
Summon it by adding one recipe to the existing global launcher, so `just -g vision` boots a Claude Code session in the repo with the skill active and qmd queryable.
Grow it with a human-gated loop: at session end an evidence-backed review distills candidate learnings into a review queue, a human promotes the accepted ones into the skill's reference catalog or a promoted-learnings file that joins the qmd collection, and curation deletes or truncates rather than lossy-summarizing, with per-role trust tiers.
Nothing new is built for retrieval, for the graph, or for the summon surface, because all three already exist and were verified this session.
The docs stay a dated seed while the live source and ivr testkit are ground truth, so on any doc-versus-code conflict the code wins.
Because a provenance pointer proves a unit's origin and not its currency, "code wins" is mechanized as a required use-time code or ivr check on any schema or feed claim before it is committed, and the parked codebase-sync staleness check is the eventual automation of that manual gate, not a replacement for it.

This shape rests on findings verified this session (2026-09-21) and on dated research, not on the prior draft:
- qmd 2.5.3 does BM25, vector, and hybrid query with local rerank and HyDE, runs as an MCP server, and does all inference locally via llama.cpp with no API, so it satisfies the cost-sensitive and model-portable constraints directly.
- `just -g` on this machine resolves to `~/.config/just/justfile`, which is already a launcher for agent CLI role sessions, so the summon surface is one new recipe on an existing pattern, not new infrastructure.
- 2026 evidence favors agentic and lexical retrieval first (SWE-agent and Agentless beat the upfront-RAG baseline), a skill plus a subagent for packaging (Anthropic Agent Skills, progressive disclosure), and file-based human-gated memory over memory frameworks, with curation named as the field's weakest link and unattended auto-writes named as a memory-poisoning surface.
- Phase-1 verified that a 12-doc qmd sample indexed into 242 chunks and returned correct provenance-bearing hits, that mObject's 330 named anchors survive pandoc as link targets with 47 of 50 clObject deep-links resolving, and that pandoc renders the pma_ feed tables cleanly.

Alternative considered, an LLM-extraction knowledge graph (Cognee, CocoIndex, LightRAG, OG-RAG): declined.
Each builds its graph by LLM extraction and would re-synthesize relationships the docs already state as hyperlinks, at the cost of a graph database, an LLM key, and the risk of contradicting the authoritative links.
For a small, fixed, already-cross-linked corpus this is cost without a matching gap.

Alternative considered, a memory framework (Mem0, Zep, Letta, OpenViking): declined.
These are built for multi-user product personalization and add a server or database dependency that cuts against local-first and model-portable, and a plain filesystem agent already hit 74% on LoCoMo, so the machinery is not earned here.

Alternative considered, retrieval wired as an always-on MCP tool (`qmd mcp`) and an automatic session-review writeback (Solution B in the brainstorm): parked, not chosen for the start.
MCP is the heaviest context primitive and automatic writes are the security surface the research flags, so this is the earned upgrade if shelling out to qmd proves clunky or if human-gated promotion proves too slow, not the starting point.

Alternative considered, the full platform with sysadmin, a materialized graph, and a staleness check (Solution C): parked.
The phase-1 finding that one-hop link-following likely suffices means the graph is unproven-needed, and the sysadmin role is a designed-for secondary, so these are grow-into pieces, not the first build.

## Success criteria

Every co-primary feed and class/message reference in scope is represented in the derived corpus, checkable by count against the source. `[executed-check]`
For a chosen field name, retrieval over the corpus returns the feed that sets it and its type, with no false positive from a near-miss name. `[executed-check]`
A known class-to-message or feed-to-feed relationship can be followed entirely within the corpus by resolving preserved links, reading only the units on the chain. `[executed-check]`
No derived unit needed to answer a single question exceeds an agreed per-unit token budget. `[executed-check]`
Every derived unit carries a pointer to its frozen source. `[executed-check]`
Asked for a field's type or a feed's field set, the expert returns the answer and flags it as requiring a live-source or ivr check before a feed or schema commit, rather than presenting the dated doc as current. `[executed-check]`
Running `just -g vision` starts a Claude Code session in which the vision-expert skill is active and a sample field-to-feed question is answered from the corpus with provenance, in one command. `[executed-check]`
A learning verified against code or ivr in one session can be captured to the review queue, promoted by a human, re-indexed, and returned by retrieval in a later session, with nothing unreviewed entering the expert's knowledge. `[executed-check]`
The summoned expert completes one real co-primary task (the End artifact) using only the knowledge base, and the result checks out against code or the ivr testkit. `[judgment]`

## Seams

Independently checkable pieces, in blast-radius order:

1. Ingest: convert docs to the markdown corpus, shred the oversized message files at their anchors, stamp provenance.
   Highest blast radius because everything downstream inherits its output and a bad ingest cannot be repaired cheaply.
   Check: the corpus exists, counts match the source, each unit traces to its origin, no unit exceeds the budget.
2. Access: index the corpus with qmd and confirm retrieval answers a real feed or schema question over budget-sized units.
   Check: a sample field-to-feed question returns the right unit, ranked, with provenance, reading no raw HTML.
3. Traversal: confirm the preserved cross-references resolve within the corpus.
   Check: a known class-to-message deep-link chain is followable entirely inside the converted units.
4. Summon: the vision-expert skill plus the launcher recipe boot an expert session with retrieval wired.
   Check: `just -g vision` yields a session where the skill is active and a sample question is answered from the KB with provenance.
5. Grow: capture verified findings, promote by human review, re-index, resurface.
   Check: a learning verified this session is promoted and returned by retrieval in a fresh session, and nothing unreviewed entered the knowledge.

Piece 1 is a prerequisite to all others.
Pieces 2 and 3 verify separately.
Piece 4 depends on 1 through 3.
Piece 5 depends on 1 through 4.

## Known vs guessed

Verified this session (2026-09-21):
Environment: qmd 2.5.3 installed with local hybrid retrieval plus MCP and sqlite-vec-backed vectors, pandoc 3.5, `just` 1.58.0 with `-g` resolving to the existing `~/.config/just/justfile` agent launcher, and no graph tool installed.
Corpus: 211 .htm in docs/original/, 66 pma_ (38 with Field/Vision/Type/Description feed tables carrying grouped header rows, 27 with Position/Form-Id report-parameter specs), 22 cl class files, 28 m message files, mObject.htm at ~213KB with 330 uppercase named anchors, 31 files deep-linking into those anchors, and docs/ is a Jekyll site rooted at docs/.
Phase-1 findings carried as verified: mObject converts with all 330 anchors preserved as link targets, clObject's deep-links resolve at 47 of 50, and a 12-doc qmd sample indexed into 242 chunks returning correct provenance-bearing hits.
Research consensus (dated 2026, primary sources for retrieval and skills, secondary and vendor-ballpark for memory numbers): agentic and lexical retrieval first, skill plus subagent packaging with progressive disclosure, file-based human-gated memory over frameworks, curation as the weak link, auto-writes as a poisoning surface.

Believed-unchecked:
That a repo-committed skill auto-loads in the Claude Code session the `just -g vision` recipe launches, without extra per-session config.
That qmd cleanly indexes the full converted corpus at scale, since only a 12-doc sample was proven.
That the other 27 m files follow mObject's anchor-per-message structure, since only mObject was confirmed.

Guessed:
That one-hop link-following plus BM25 reverse lookup covers the traversal need without a materialized graph.
If wrong, the fix is graphify or a small href-to-adjacency script, additive and reversible, not a change to the corpus.
That human-gated promotion is a cadence the user will sustain.
If wrong, the fix is the parked auto-write tier with decay and shadow-mode, not a change to the corpus.
That a single pandoc pass handles the dirty HTML per family cleanly.
If wrong, ingest needs per-family parse rules, which changes ingest effort but not the chosen shape.

## Parking lot

- Upgrade retrieval to the `qmd mcp` tool and an automatic session-review writeback (Solution B).
  Restart context: adopt only if shelling out to `qmd query` proves clunky in practice or human-gated promotion proves too slow, because MCP is the heaviest context primitive and auto-writes are the poisoning surface, so build it in shadow-mode first.
- Add an auto-write grow tier with decay.
  Restart context: the parked hands-free accumulation option, LRU or priority decay to fight bloat, gated behind a measured failure of the human-gated cadence, shadow-mode before it touches the live knowledge.
- Extend the KB to the sysadmin role.
  Restart context: secondary role, sources are nix-build.md, adm_ pages, Running.htm, update-malloc-debugging.md, docs/VdbScan/, docs/year-end/, most already markdown so ingest is light, drifts fastest because the .csh scripts are live and has the weakest ivr coverage, the mechanism is designed for it so this is a corpus addition not a redesign.
- Materialize the cross-reference graph if link-following underperforms.
  Restart context: build a deterministic adjacency from the preserved hrefs and anchors via graphify (`uv tool install graphifyy`, no server, no vector store, no LLM) or a small script, test on 5 to 10 real .htm files first because its markdown-link path is unverified on this HTML.
- Build the codebase-sync staleness check.
  Restart context: a build-time check that diffs software/src/ and application/production/scripts/ since the KB's last sync and flags units describing changed areas as possibly stale, ProcessUpdates.csh is currently modified as a live example.
- Graph the C++ kernel for the code-anchored verifier.
  Restart context: deferred code phase, code-graph-mcp (SQLite + BM25 + sqlite-vec, local, no server) is the lighter candidate, but tree-sitter may struggle with a macro-heavy kernel, so test extraction fidelity on a sample first.
- Capture the real diagram images as cached text.
  Restart context: ~100 images in docs/original/, most chrome but the concept and tutorial diagrams carry real content, describe once at ingest and cache beside the doc, never analyze per session.

## Out of scope

Any LLM-extraction knowledge graph, external graph database, or vector store beyond qmd's own local index.
Any memory framework (Mem0, Zep, Letta, OpenViking) or the separate headroom sqlite_vector store, because one retrieval backbone is qmd.
An automatic, unattended memory-write loop, deferred in favor of human-gated promotion.
The Jekyll publish layer, which renders the docs as a website and is not KB content.
Editing the frozen docs/original/ files, which stay a faithful dated snapshot while the corpus is derived alongside them.
