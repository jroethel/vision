- Anchor names repeat within a file (same message documented once per
  defining class, e.g. asSelf for Boolean/FALSE/TRUE) and some differ only

  occurrences get `-2`, `-3`... suffixes. Without this the on-disk unit

  keep their own units but do not override the link target, so
  `mFile.htm#name` resolves to the class's own definition.

  in the vocabulary); titles are `Message XRef: <letter>`, first chunk
  carries the letter as its anchor for provenance only. No anchors are
  registered for mXRef, per plan.
- Plain file-level links into m*.htm (e.g. `](mDate.htm)`, ~12) stay
  unresolved: the plan registers only per-message anchors, and there is no
  natural first unit for a message file.
- m-file preambles (the class profile hierarchy trees) are dropped,
  implied by the units == anchors invariant; the same profile content
  lives in the cl*.htm docs, which are ingested in full.
