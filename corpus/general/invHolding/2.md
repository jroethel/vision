## The Holding Class

The following key messages are defined for the class Holding:

**Property**

**Returns**

account

Account instance represented by holding

security

Security instance represented by holding

date

Date represent by holding

baseCurrency

Currency in which monetary values are represented (initialized to account's value)

\_shares

Unadjusted shares owned by account in security

shares

Split adjusted shares owned by acct in security

\_totalMarketValue

Unadjusted market value of shares owned using price on holding date in baseCurrency

totalMarketValue

Currency adjusted market value

\_totalCost

Unadjusted cost of shares owned in baseCurrency

totalCost

Currency adjusted cost

percentOfPort

Weight of this holding by market value relative to market value of account

percentOfEquity

Weight of this holding by market value relative to equity market value of account

Each Holding responds to the messages *security* and *account* by returning an instance of those classes; therefore, any messages defined at Security or Account can be referenced via a specific Holding. The message *id* has been defined at Holding to return a string in the form *securityCode---accountCode*. For example, the *id* for a holding of security GM in portfolio XYZ would display as:

      37044210---XYZ

Unlike the entity classes described so far, you do not create holdings directly. Instead various methods have been defined which can be used as part of the production cycle or interactively to create and maintain holdings.
