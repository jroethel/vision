### Support and Table Classes

Two additional abstract subclasses, **Support** and **Table** are recommended for organizing classes that require objects that are individually named that are not really core entities in the application. Note that these classes may need to be [added to your database](#missingDefs) if you want to use them. There is no special protocol that needs to be defined for these classes. They simply provide a way of organizing the entity subclasses so that the expression:

      Entity showInheritance

neatly separates the core entity classes from miscellaneous support classes. For example, you could create a subclass of **Table** when you need a place to store descriptions for coded information.
